### 2.2 静态优先流水线 (StaticFirstPipeline) - 默认推荐

**文件**: `code-graph-system/backend/pipeline/static_first_pipeline.py`

**核心理念**: 静态分析产出高置信度结构数据，AI 增强补充语义信息。

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 1: FileIndexStage (异步文件索引)                                           │
│   • 扫描仓库所有源码文件                                                          │
│   • Git 增量检测（对比 commit SHA）                                               │
│   • 输出: FileInfo 字典                                                          │
│   • 置信度: N/A (元数据)                                                         │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 2: DeepStaticAnalysisStage (深度静态分析)                                  │
│   • 并行 AST 解析 (ThreadPoolExecutor/ProcessPoolExecutor)                       │
│   • 检测框架模式 (Spring @Service/@Controller/@Repository 等)                    │
│   • 产出 A (持久化): structural_nodes, structural_edges                          │
│   • 产出 B (临时): import_graph, framework_patterns, low_confidence_edges        │
│   • 置信度: 0.80-0.98                                                            │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    │           并行执行              │
                    ▼                               ▼
┌───────────────────────────────┐   ┌───────────────────────────────────────────┐
│ Stage 3: DirectoryClusterStage│   │ Stage 4a: SpringDIEventStaticStage        │
│ (目录聚类，零 LLM)            │   │ (Spring DI/Event 静态解析，零 LLM)         │
│                               │   │                                           │
│ • 基于目录结构聚类             │   │ • 解析 application.yml/application.      │
│ • 产出: ModuleCandidate 列表  │   │   properties                              │
│                               │   │ • 解析 @Autowired/@KafkaListener/@       │
│                               │   │   RabbitListener                         │
│                               │   │ • 产出: di_event_edges, ambiguities       │
└───────────────────────────────┘   └───────────────────────────────────────────┘
                    │                               │
                    └───────────────┬───────────────┘
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 3b: AISemanticEnhanceStage (AI 语义增强)                                   │
│   • 两次 LLM 调用:                                                               │
│     - 调用 A (必发): 确认模块边界 + 语义描述                                       │
│     - 调用 B (按需): 低置信度边验证                                               │
│   • 并发处理模块 (ThreadPoolExecutor)                                             │
│   • 产出: ModuleEnhancement, ai_nodes, ai_edges                                 │
│   • 置信度: 0.65-0.75                                                            │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 4b: SpringDIEventAIStage (AI 解析歧义)                                     │
│   • 仅处理静态无法解析的歧义                                                       │
│   • 产出: ai_di_edges                                                            │
│   • 置信度: 0.70-0.80                                                            │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 5: DataLineageExtractionStage (数据血缘提取)                                │
│   • 零 LLM 调用                                                                  │
│   • 提取 Repository→Database, Service→Service flow                              │
│   • 产出: lineage_nodes, lineage_edges                                          │
│   • 置信度: 0.85-0.95                                                            │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 6: GraphMergeWithQualityStage (合并 + 质量报告)                             │
│   • 合并所有节点和边                                                              │
│   • 字段级合并策略:                                                               │
│     - 静态节点保留高置信度 source/confidence                                      │
│     - AI 字段追加，不覆盖静态数据                                                 │
│   • 产出 QualityReport:                                                          │
│     - static_node_ratio (静态节点占比)                                            │

└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 7: AIDescriptionStage (AI 描述生成，可选)                                  │
│   • 按领域分组节点                                                                │
│   • 批量生成自然语言描述                                                          │
│   • 产出: description 字段追加到节点 properties                                   │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ 持久化层                                                                         │
│   • GraphRepository.save() → data/graphs/{graph_id}.json                        │
│   • GraphStorage.save_graph() → API serving 层 (内存缓存)                        │
│   • RAG 向量化 (可选) → ChromaDB                                                 │
│   • Neo4j (可选) → 图数据库                                                      │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**静态优先流水线置信度体系**:

| 数据来源 | 置信度范围 | 说明 |
|---------|-----------|------|
| 静态分析 (直接导入) | 0.95-0.98 | import 语句、类继承 |
| 静态分析 (注解驱动) | 0.85-0.95 | Spring @Autowired, @Service |
| 静态分析 (框架模式) | 0.80-0.90 | Repository→Database 映射 |
| AI 语义增强 | 0.65-0.75 | 模块边界、语义描述 |
| AI 歧义解析 | 0.70-0.80 | 解析无法静态确定的 DI/Event |

### 2.3 AI 优先流水线 (AIFirstPipeline)

**文件**: `code-graph-system/backend/pipeline/ai_first_pipeline.py`

**核心理念**: 完全由 AI 驱动，产出实体级、字段级血缘。

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 1: AIRepositoryScanStage (AI 探索仓库结构)                                 │
│   • AI 使用工具: read_file, search_code, list_directory                         │
│   • 产出: entities, services, flows                                             │
│   • 节点类型: Entity, Table, Field                                              │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 2: AIEntityAnalysisStage (AI 分析实体字段)                                 │
│   • 并行处理实体 (ThreadPoolExecutor)                                             │
│   • 产出: EntityResult (字段定义、约束、关系)                                      │
│   • 并发控制: AI_ENTITY_CONCURRENCY (默认 3)                                      │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 3: AIFieldLineageStage (AI 推断字段血缘)                                   │
│   • 推断字段级数据流向                                                           │
│   • 边类型: one_to_one, one_to_many, many_to_many, flow_to                      │
│   • 产出: Field 节点 + 字段级边                                                   │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 4: AIEntityDescriptionStage (AI 生成描述)                                  │
│   • 生成实体描述和重要性评分                                                      │
│   • 产出: description, importance_score 字段                                     │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ Stage 5: AIGraphBuildStage (构建图谱)                                            │
│   • 构建 GraphNode 和 GraphEdge                                                  │
│   • 生成质量报告                                                                 │
│   • 持久化                                                                       │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**AI 优先流水线特点**:

| 特性 | 说明 |
|-----|------|
| 完全 AI 驱动 | 无静态分析前置，适用于非标准框架项目 |
| 字段级血缘 | 追踪数据在字段级别的流转 |
| 实体重要性评分 | AI 评估实体在系统中的重要性 |
| 节点类型 | Entity, Table, Field, FlowNode |
| 边类型 | flow_to, one_to_one, one_to_many, many_to_one, many_to_many |

|-------|------|---------|-------|

| `CallGraphAgent` | 调用图分析 | - | calls, async_calls |
| `DataLineageAgent` | 数据血缘追踪 | DataSource, DataSink | reads, writes, produces |
| `APIEndpointAgent` | API 端点分析 | API, APIEndpoint | routes_to, handles |
| `CrossModuleAgent` | 跨模块依赖 | - | depends_on |

### 3.2 异步分析任务流程

**文件**: `code-graph-system/backend/api/routers/analysis.py`

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                          POST /analyze/repository                                │
│   参数: repo_path, repo_name, branch, depth, pipeline_mode                      │
│   立即返回: {task_id, status: "pending"}                                         │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│                          Celery 任务提交                                         │
│   ├── celery_analyze.apply_async()                                              │
│   ├── Redis 登记任务 ID                                                          │
│   ├── status_store.set_analyzing(repo_id, task_id)                              │
│   └── analysis_store.write_completed(status="analyzing")                        │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│                     Celery Worker 执行 (celery_analyze)                          │
│                                                                                 │
│   1. Git URL 克隆 / 缓存检查                                                     │
│      ├── 本地路径: 直接使用                                                      │
│      ├── Git URL: 克隆到 data/repos/{repo_name}/                                │
│      └── 已存在: 检查 commit SHA 是否变化                                        │
│                                                                                 │
│   2. 根据 pipeline_mode 选择流水线                                               │
│      ├── "ai_first" → AIFirstPipeline                                          │
│      └── "static_first" (默认) → StaticFirstPipeline                            │
│                                                                                 │
│   3. 执行分析流水线                                                              │
│      ├── 发布进度事件到 Redis Pub/Sub                                           │
│      │   channel: progress:{task_id}                                            │
│      │   格式: {step, total, stage, message, status}                            │
│      │                                                                          │
│      └── 错误处理: 捕获异常，发布 failed 事件                                    │
│                                                                                 │
│   4. 持久化图谱                                                                  │
│      ├── GraphRepository.save() → data/graphs/{graph_id}.json                  │
│      └── GraphStorage.save_graph() → API serving 层                             │
│                                                                                 │
│   5. 完成通知                                                                    │
│      ├── status_store.set_completed()                                           │
│      └── 发布 completed 事件                                                     │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│                    GET /analyze/stream/{task_id} (SSE)                           │
│                                                                                 │
│   • 订阅 Redis Pub/Sub channel: progress:{task_id}                              │
│   • 事件格式:                                                                    │
│     {                                                                           │
│       "step": 3,                                                                │
│       "total": 7,                                                               │
│       "stage": "AISemanticEnhanceStage",                                        │
│       "message": "正在分析模块: user-service",                                   │
│       "status": "running",                                                      │
│       "elapsed_seconds": 45                                                     │
│     }                                                                           │
│   • 完成时: {status: "completed", graph_id, node_count, edge_count}             │
│   • 心跳: 每 15 秒发送 ping                                                      │
```

## 七、总结

该项目采用分层架构，实现了从代码仓库到知识图谱的完整转换流程：

### 核心特点

1. **双模式分析流水线**
   - 静态优先模式：通过并行执行和分阶段处理，将 LLM 调用量降低 50% 以上
   - AI 优先模式：完全 AI 驱动，支持字段级血缘和实体重要性评分

2. **异步任务系统**
   - Celery + Redis 实现异步分析
   - SSE 实时进度推送
   - 断点续跑支持

3. **多级存储**
   - 本地 JSON (默认)
   - Neo4j (可选图数据库)
   - ChromaDB (可选向量索引)

4. **前后端分离**
   - React 前端通过 Zustand 管理状态
   - SSE 监听实时进度
   - Cytoscape.js 渲染图谱

### 数据流向概览

```
代码仓库 → 预处理 → 分析流水线 → 图谱构建 → 持久化 → API 服务 → 前端展示
```
